# Запуск пилота

Пилот — это сервис на одном компьютере предприятия, к которому люди ходят
по адресу в локальной сети завода. Данные в нём настоящие: заказы из
выгрузок 1С, изделия и нормы, деньги, склад. Онлайн-связи с 1С и Битрикс
пока нет — это следующий этап (см. «Чего в пилоте нет»).

Команды ниже запускаются из корня репозитория. На Windows — в PowerShell
или cmd, они те же.

## Один раз: подготовка

### 1. Компьютер

Любой компьютер в сети завода, который не выключают (либо VPS — тогда
раздел «Деплой» в README). На нём нужны Docker Desktop, Node 22+ и Git.
У компьютера должен быть постоянный адрес в сети — попросить у того, кто
ведёт сеть (например `192.168.1.20`). Узнать текущий: `ipconfig` на
Windows, `ifconfig` на macOS.

```bash
git clone <адрес репозитория> cmk-avrora-erp
cd cmk-avrora-erp
npm run install:all
```

### 2. Перенос базы

Боевая база сейчас живёт в Docker на ноутбуке разработки. Она должна
переехать туда, где будет сервер.

На ноутбуке разработки:

```bash
npm run db:backup перенос
```

Файл появится в `backend/backups/erp_production_db-manual-<дата>-перенос.dump`.
Скопировать его на сервер в ту же папку `backend/backups/`.

На сервере:

```bash
npm run db:up
docker exec -i erp_postgres pg_restore -U erp_user -d erp_production_db --clean --if-exists --no-owner < backend/backups/<файл>.dump
npm --prefix backend run prisma:push
npm --prefix backend run apply-views
```

### 3. Чистка данных

Один раз, на той базе, которая станет боевой. Скрипт убирает 43 строки
мок-синхронизации и демо-заказ ORD-2026-001; если найдёт не то количество
строк — откатится сам и ничего не удалит.

```bash
npm run db:backup перед-чисткой
docker exec -i erp_postgres psql -U erp_user -d erp_production_db -v ON_ERROR_STOP=1 < backend/backups/cleanup-canned-lines-2026-09-06.sql
```

В конце скрипт печатает `canned_left 0, demo_left 0`.

### 4. Запуск

```bash
npm run pilot
```

Первый запуск собирает образ 3–5 минут. Команда сама заполнит секреты в
`backend/.env`, поднимет базу, сервер и ежедневные бэкапы. Windows при
первом старте спросит про сетевой доступ для Docker — разрешить.

Адрес для людей: `http://<адрес-компьютера>:3000`, например
`http://192.168.1.20:3000`. Его можно отправить в общий чат и положить на
рабочий стол закладкой.

Проверка, что всё живо:

```bash
npm run smoke http://localhost:3000
```

Все строки должны быть `PASS`. Ещё раз ту же команду — после каждого
обновления.

### 5. Пароли

Личные аккаунты только у директора и администратора; смена работает под
общим сменным аккаунтом (один PIN на цех, склад, снабжение). Пароли уже
выданы командой `rotate-passwords`; если потерялись — администратор
сбрасывает их в разделе «Настройки → Пользователи». Полная перевыдача всем:
`npm --prefix backend run rotate-passwords` (всех разлогинит).

## Каждый день и каждую неделю

**Новые заказы из 1С.** Пока 1С не подключена по сети, заказы попадают в
сервис выгрузкой CSV — тем же способом, что и раньше:
`npm --prefix backend run import:1c-csv` с теми же файлами, флаги описаны в
шапке `backend/prisma/import-1c-csv.ts`. Повторный импорт дублей не
создаёт.

**Бэкапы.** Сервис `backup` пишет дамп в `backend/backups/` сразу при
старте и потом раз в сутки, старше 14 дней удаляет. Перед любым рискованным
шагом — `npm run db:backup <пометка>`.

**Обновление.** На сервере:

```bash
git pull
npm run pilot
```

Если в обновлении менялась схема (`backend/prisma/schema.prisma`), перед
`npm run pilot` — `npm --prefix backend run prisma:push` и
`npm --prefix backend run apply-views`.

**Остановить / посмотреть логи.** `npm run pilot:down` (данные остаются),
`npm run pilot:logs`.

## Если что-то не так

- Страница не открывается: `docker ps` должен показывать `erp_api_pilot`
  и `erp_postgres` со статусом Up. Логи — `npm run pilot:logs`.
- Восстановить базу из бэкапа:
  `docker exec -i erp_postgres pg_restore -U erp_user -d erp_production_db --clean --if-exists --no-owner < backend/backups/<файл>.dump`
- Сервер стартует и сразу падает с текстом про `REQUIRE_SECRETS` —
  в `backend/.env` пустые `JWT_SECRET` или `INTEGRATION_1C_SECRET`;
  `npm run ensure-secrets` заполнит.
- `npm run dev` обрывается на `prisma db push` с текстом «Use the
  --accept-data-loss flag» — схема разошлась с базой. **Флаг не добавлять**:
  он молча снесёт то, на что жалуется. Посмотреть, что именно разошлось:

  ```bash
  cd backend && npx prisma migrate diff --from-url "$DATABASE_URL" \
    --to-schema-datamodel prisma/schema.prisma --script
  ```

  Дальше по ситуации: если различие безопасно (индекс на пустой таблице,
  переименование), примените SQL руками; если Prisma хочет убрать умолчание
  колонки, которым пользуется код, поправьте схему под базу, а не наоборот.
- Экран показывает выдуманные цифры и не ходит на сервер — в браузере
  включён режим дизайна. Он живёт в `localStorage` ключом `ui-design`,
  снимается адресом `?design=0` или очисткой данных сайта.

## Чего в пилоте нет

- **Онлайн-обмен с 1С.** Пакеты «изготовлено → списание» копятся в очереди
  (раздел «Интеграция») и уйдут, когда появится адрес HTTP-сервиса 1С и
  1С-подрядчик соберёт приём по согласованному контракту.
- **Заявки в Битрикс по контракту воронки 56.** Наши сделки несут только
  название, сумму и воронку; 1С по ним документ не создаст, пока пакет не
  дополнен строками товаров с GUID и реквизитами (файл контракта
  «ЦМК 56 Интеграция .xlsx»).
- **Обмен с НКТ** — ждёт ключ API в `backend/.env` (`NKT_API_KEY`).
- **Доступ снаружи завода и HTTPS** — это профиль `prod` на VPS с доменом,
  раздел «Деплой» в README.
- **Автосписание сырья при отметке «изготовлено»** — по решению бизнеса
  сырьё списывает кладовщик руками, пока 1С не пришлёт процедуры.
