# Правило заполнения данных

Чтобы данным можно было верить, у каждого поля должен быть один хозяин.
Если одно и то же можно поменять в двух местах, они разойдутся, и никто не
скажет, какое значение верное.

Хозяев три: **1С**, **таблица инженера**, **сам сервис**.

## Кто чем владеет

| Данные | Хозяин | Как попадает | Править руками в сервисе |
|---|---|---|---|
| Заказы, позиции, суммы, даты | 1С | `npm run import:1c` | нельзя |
| Контрагенты, БИН | 1С | тот же импорт | нельзя |
| Договоры-основания, оплаты | 1С | тот же импорт | оплату можно добавить, если её нет в 1С |
| Приходы материала, партии, цены закупа | 1С | тот же импорт | нельзя, приход руками закрыт |
| Остатки материалов | 1С | тот же импорт | только списание в производство |
| Склады, организации | 1С | тот же импорт | нельзя |
| Состав изделия (BOM) | таблица инженера | `npm run import:catalog` | можно, это область конструктора |
| Нормы труда | таблица инженера | тот же импорт | можно |
| Утверждённые цены | таблица инженера | `npm run import:catalog --prices` | через пересмотр цены директором |
| План производства | сервис | руками | да, плановик |
| Минимальные остатки | сервис | руками | да, кладовщик |
| Склад обрезков | сервис | руками | да, кладовщик |
| Объект (БС) на позиции | сервис | руками | да, в карточке заказа |
| Акты приёма-передачи | сервис | руками | да, из карточки заказа |
| Отметка «изготовлено» | сервис | руками | да, цех |

Правило одной строкой: **если данные есть в 1С, сервис их только читает.**
Всё, что 1С не знает, живёт в сервисе и правится в нём.

## Порядок перезаполнения

Ниже полный проход. Если нужно только добить недостающее, шаги 1 и 2
пропускаются, а импорты запускаются как есть — они не создают дублей.

### 0. Бэкап

```bash
npm run db:backup перед-перезаливкой
```

Файл ляжет в `backend/backups/`. Без него дальше не идти.

### 1. Выгрузка из 1С

Оператор 1С готовит файлы CSV (кодировка UTF-8, разделитель `;`):

| Файл | Что внутри |
|---|---|
| `ЗаказыШапки.csv` | шапки заказов клиента и поставщику |
| `ЗаказыСтроки.csv` | строки этих заказов |
| `Номенклатура.csv` | справочник изделий и материалов |
| `Контрагенты.csv` | контрагенты с БИН |
| `Оплаты.csv` | оплаты по договорам |
| `Остатки.csv` | остатки материалов с партиями |

Первые три обязательны, остальные по мере готовности.

### 2. Заливка 1С

```bash
npm run import:1c -- --headers ЗаказыШапки.csv --lines ЗаказыСтроки.csv --nomenclature Номенклатура.csv \
  --contractors Контрагенты.csv --payments Оплаты.csv --stock Остатки.csv
```

Импорт идемпотентный: повторный запуск того же файла не создаёт дублей.
Полная перезаливка с очисткой операционных данных — добавить `--wipe --yes`,
и только сразу после бэкапа.

Материалы автоматически не создаются: неопознанные попадают в отчёт в конце
прогона. Это не ошибка импорта, это список для оператора 1С.

### 3. Состав и нормы из таблицы инженера

В Google Таблицах два листа. Выгрузка: **Файл → Скачать → CSV**.

**Лист «Состав»** — из чего делается изделие:

| Артикул | Материал | Количество | Операция |
|---|---|---|---|
| n-059 | С0104 | 0,44 | резка |
| n-059 | Л0077 | 0,02 | покраска |

- **Артикул** — код изделия из справочника, ровно как в сервисе.
- **Материал** — код материала или его полное наименование.
- **Количество** — расход на одно изделие. Запятая и точка равнозначны.
- **Операция** — `резка`, `сборка/сварка`, `обшивка`, `покраска`.
  Колонку можно не заполнять, тогда принимается `сборка/сварка`.

**Лист «Нормы»** — сколько людей и часов на одно изделие:

| Артикул | Передел | Человек | Часов |
|---|---|---|---|
| n-059 | резка | 2 | 0,25 |
| n-059 | сборка | 1 | 1,5 |
| n-059 | покраска | 1 | 0,5 |

Переделов ровно три: `резка`, `сборка`, `покраска`. Порядок строк не важен,
лишние колонки игнорируются, порядок колонок любой.

Сначала проверка, она ничего не пишет:

```bash
npm run import:catalog -- --bom состав.csv --norms нормы.csv
```

Отчёт покажет: сколько строк принято, какие артикулы и материалы не нашлись,
где плохие числа и повторы. Пока в отчёте есть незнакомые коды, писать рано:
поправьте таблицу и повторите проверку.

Когда отчёт устраивает:

```bash
npm run import:catalog -- --bom состав.csv --norms нормы.csv --apply
```

Если состав изделия в таблице полный и надо выкинуть из базы всё лишнее,
добавьте `--replace`. Без него строки только добавляются и обновляются.

### 4. Пересчёт себестоимости

Состав и нормы сами по себе цену не считают.

```bash
npm run recalc:costing -- --active
```

Считает по изделиям в активных заказах. Без `--active` пересчитает все,
у кого есть состав или нормы, это дольше.

### 5. Цены прайса

**Лист «Прайс»** — утверждённая цена изделия:

| Артикул | Цена |
|---|---|
| n-059 | 123 456,78 |

```bash
npm run import:catalog -- --prices прайс.csv           # проверка
npm run import:catalog -- --prices прайс.csv --apply   # запись
```

Каждое изменение цены пишется в историю от имени директора: утверждённая
цена в файле — уже его решение. Совпадающие цены не трогаются.

Старый файл «Прайс - Лист1.csv» с колонками по номерам грузится прежней
командой `npm run import:price-list -- --file …`.

### 6. Проверка

```bash
npm run check:data
```

Отчёт делится на три части: что пришло из 1С, что заполняет инженер, что
заполняется по ходу. Строки помечены так:

- `ok` — заполнено;
- `~` — работать можно, но часть цифр будет неполной;
- `СТОП` — экран покажет пустоту или неверное число.

Чтобы получить сами коды изделий, которые надо добить:

```bash
npm run check:data -- --list
```

## Как понять, что заполнено правильно

Проверка выше отвечает на «всё ли на месте». На «верно ли» отвечают три
сверки, каждая внутри сервиса:

1. **Деньги.** Раздел «Деньги» → «Сверка с закупом»: суммы заказов против
   договоров-оснований. Расхождение значит, что часть документов не
   выгрузилась из 1С.
2. **Себестоимость.** Карточка изделия → «Себестоимость»: расчёт против
   утверждённой цены. Отклонение больше 5 % поднимается директору само.
3. **Склад.** Раздел «Материалы» → «Партии и резервы»: цены закупа с
   аномалией отмечены отдельно. Цена, отличная от медианы в пять раз, почти
   всегда опечатка в 1С, а не реальная закупка.

## Чего делать нельзя

- Править в сервисе то, чем владеет 1С. Следующая выгрузка это затрёт, и
  правка пропадёт молча.
- Запускать `--wipe` без свежего бэкапа.
- Заводить материалы и изделия ради того, чтобы импорт «прошёл целиком».
  Неопознанная строка — это вопрос к 1С, а не к сервису.
- Гонять импорт синхронизации 1С на боевой базе ради проверки. Для проверок
  есть копия базы.
