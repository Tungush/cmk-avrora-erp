# Анализ Google-таблицы «2025_План Производства» и проект переноса в ЦМК АВРОРА

Источник: `2025_План Производства (1).xlsx` — 44 листа, из них 7 скрытых.
Проанализировано: структура, ~500 000 формул, межлистовые ссылки.

## 3. Разбор ключевых листов

### 3.1. `Telecom` — реестр заказов (66 колонок)

Строка = **позиция заказа** (не заказ целиком). Шапка на строке 3, данные с 4-й.

**Что вводит пользователь (18 из 66 колонок):**

| Кол. | Поле | Кол. | Поле |
|---|---|---|---|
| A | Тип (ГП / …) | V | План вывоза |
| C | Наименование | AA | Дата резерва |
| D | Кол-во | AD | Отгружено |
| E | ед.изм | AF | № АПП |
| F | БС/сайт | AG | Дата отгрузки |
| G | Номер заказа АС | AO | Фиксация по ВЗ |
| I | Регион | AP | Комментарии |
| K | Заказчик | AC | Статус сделки |
| L | Цена за 1 ед | S | Дата заявки |
| T | План квартал | U | ФЗ / ВЗ |

**Ключевые формулы (что система должна считать сама):**

```excel
B  Артикул      = VLOOKUP(C; Артикулы!B:C; 2)        → артикул по наименованию
J  Руководитель = IF(K="Радикс"|"ТНС+";"Алитет"; IF(K="КарТел";"Артур"; …))
M  Сумма с НДС  = D * L
W  Просрочка    = IF(AD>0;""; IF(сегодня < V;""; сегодня − V))
Z  Резерв       = VLOOKUP(B; 'Склад ГП'!B:X; 6)
AE Остаток      = D − AD
AH Дней до опл. = (AG + 30) − TODAY()                 → отсрочка 30 дней
AI Просрочка    = IF(AH < 0; "Просрочка"; "")
AL Сумма ГП     = L * Z
AM Сумма к изг. = AC * L
AZ Тоннаж       = Артикулы.ТоннажЗаЕд * D
BA Себестоим.   = 'Спецификации 2022'.Цена * D
BF План произв. = SUMIFS(M; по номеру заказа)
BG Затраты      = SUMIFS('19.20-7п'!M; по номеру заказа)
BH Маржа        = BF − BG
```

> **Вывод:** 48 из 66 колонок вычисляются. В веб-форме пользователь заполняет ~18 полей, остальное показывается как read-only.

### 3.2. `План` — ядро планирования (88 колонок)

Строки 1–5 — шапка и итоги, данные с 6-й. Одна строка = один артикул.

**Главная формула всей книги (колонка P, «Изготовить»):**

```excel
P = MAX(0; L − (M + O + N)) + F + E

где  L = SUMIFS(Telecom!D)        — заявка от телекома, шт
     M = Склад ГП, остаток        — уже на складе
     N = SUMIFS(Telecom!Z)        — резерв на отгрузку
     O = Склад ГП, вывоз          — вывезено
     F = Минимальные остатки      — норматив запаса
     E = Доп. заявка              — ручная корректировка
```

Правая часть листа (колонки R…CJ) — это **разложение плана по периодам**: 4 квартала + 12 месяцев + 53 недели. Каждая ячейка — `SUBTOTAL`/`SUMIFS` по `Telecom` с фильтром по неделе/месяцу из колонок `Telecom!AT:AV` (месяц/неделя/год плана вывоза).

Прочее:
```excel
A = SUMIF('Спецификации 2022'!F:F; D; …!I:I)     — расход материала на план
I = VLOOKUP(C;'Прайс'!C:Z;6)                     — цена, fallback → последняя цена из Telecom
J = G * I                                        — сумма на план
```

### 3.3. `Спецификации 2022` — BOM + калькуляция себестоимости (42 колонки)

Двухуровневая структура: строка-заголовок изделия (арт. `k-001`) + строки-компоненты под ней.

**Нормы расхода:**
```excel
E  Материал  = VLOOKUP(F; 'База сырья'!E:AA; 17)
O  Коэф.     = IFS(ед="м"|"м2"|"л"|"шт"; 'База сырья'.вес_ед;  ед="кг"; G)
Q  Масса     = IF(ед="кг"; G; G * O)
S  Цена ед.  = VLOOKUP(F; 'База сырья'!E:J; 6)
T  Сумма     = S * G
I  На план   = VLOOKUP(B; 'План'!C:Z; 5) * G        ← обратная связь с «План»
```

**Калькуляция (трёхпередельная):**

| Передел | Люди | Часы | Стоимость |
|---|---|---|---|
| Резка | Y | Z | `AA = Z*Y*X` |
| Сборка / сварка / обшивка | AB | AC | `AD = AC*AB*X` |
| Зачистка / покраска | AE | AF | `AG = AF*AE*X` |

где `X` = оклад ср./час (2 040 ₸, тянется из `ЗП сотр.`).

```excel
AH Общ. чел/час = (Z*Y) + (AB*AC) + (AE*AF)
AI Себест.труда = AA + AD + AG
AJ Логистика    = W * 3%          (W = цена материалов)
AK Вода/газ/эл. = W * 1%
AM Себестоимость= W + AI + AJ + AK
AN Маржа        = AM * 10%
AP Цена         = AM + AN
```

Коэффициенты 3% / 1% / 12% (НДС) / 10% (маржа) лежат в строке 1 — **это конфигурация, а не данные.**

### 3.4. `Др проекты` — второй реестр заказов (67 колонок)

Отличается от `Telecom` тем, что здесь **три платежа вместо одного** и явная привязка к договорам-основаниям:

```excel
AC Остаток к оплате = R − W − Y − AA − V
                      (сумма − аванс − постоплата1 − постоплата2 − штраф)
AE Остаток к изгот. = IF(AG>0; F−AJ−AG; F−AJ)
BB № ДО               = VLOOKUP(BA; '19.20-7п'!B:Z; 9)
BC Сумма по ДО       = SUMIFS('19.20-7п'!M; по ДО)
BD Оплачено          = SUMIFS('19.20-7п'!N; по ДО)
BE Не оплачено       = SUMIFS('19.20-7п'!O; по ДО)
BF Авансовая сумма   = IF(нет отгрузки; R*%предоплаты − платежи; R − платежи)
BK Отгружен?         = IF(дата отгрузки=""; "нет"; "да")
N  Статус в отчёте   = VLOOKUP(A; '7.28'!A:C; 3)     ← из выгрузки 1С
BN Оплачено по гугл  = SUMIFS('приходы др проектам'!R; по номеру заказа)
```

### 3.5. `приходы др проектам` — платежи поставщикам (30 колонок)

Полностью ручной ввод, **ни одной ссылки на другие листы**. Одна строка = один платёж по ДО.

Поля: № ДО, дата ДО, № счёта, дата счёта, группа проектов, ответственный закупщик, утвердитель, заказчик, БИН/ИИН *(«Обязательно заполнять!»)*, поставщик, валюта, общая стоимость, оплаченная сумма (1С), категория ДО, статья доходов/расходов, заказ на продажу, дата оплаты.

```excel
S Неоплаченная = Q − SUMIFS($R:$R; $E:$E; E)    — общая минус все платежи по этому ДО
X/Y/Z          = TEXT(дата;"mmmm") / "yyyy" / WEEKNUM   — разрезы для отчётности
```

> Один ДО = несколько строк-платежей. В БД это классическая пара `PaymentDocument` 1—N `Payment`.

### 3.6. `свод Акерке` — сверка заказ ↔ ДО ↔ стадия сделки (68 колонок)

Шапка на строке 4, данные с 5-й. Назначение — свести три источника:

```excel
G  Подтверждено = SUMIFS(Telecom!M; Telecom!H; A)      — по номеру заказа А77
H  Расхождение  = E − G                                — заявлено минус подтверждено
X  Сумма по ДО  = SUMIFS('19.20-7п'!M; '19.20-7п'!B; M)
Y  Дельта       = X − V
BF Стадия       = INDEX(BN:BN; MATCH(BG; BO:BO)) & "." & BG
BL Статус       = VLOOKUP(BG; BO:BP; 2)
```

Справочник стадий сделки лежит **в самом листе** (диапазон `BN5:BP36`) — в новом сервисе это таблица-справочник.

Два логических блока в шапке: **«Долги по АПП — Телеком»** (кол. AB) и **«Долги — 71п, внешние Заказчики»** (кол. AQ).

### 3.7. Складской контур

```
Приход ГП ──────► Склад ГП ──────► Сводная по ГП
   (ввод)          (расчёт)          (отчёт)
```

`Склад ГП`, колонка G — остаток:
```excel
G = (I + E + F) − (O + S)
    приход + корректировки − отгрузки − списания
I = SUMIF('Приход ГП'!G; артикул; …!I)     — всего принято
N = MAXIFS('Приход ГП'!E; …)               — дата последнего прихода
```

`Минимальные остатки`:
```excel
H Готовность %    = MIN(1; факт / норма)
I Нужно для вып.  = MAX(0; норма − факт)
L Нужно изготовить= MAX(0; норма − факт + (план_вывоз − вывезли))
```

`На закуп` — дефицит сырья:
```excel
P Потребность = SUMIFS(Telecom!D; артикул; неотгруженные)
Q Дефицит     = IF(P=0; 0; IF(остаток > P; 0; остаток − P)) * −1
S Сумма       = Q * цена
```

### 3.8. Отчётные листы

| Лист | Логика |
|---|---|
| `Сводка` | 14 659 ссылок на `Telecom`. Матрица `SUMIFS` по срезам: квартал × регион × заказчик × ФЗ/ВЗ, с фильтром `Статус <> "отмена"` |
| `Сводная по ГП` | По артикулам: по заявкам / резерв / мин. остаток / отгружено по годам 2022–2025 (`SUMIFS(Telecom!AD; …; Telecom!AS; "2024")`) |
| `Долги по отгрузкам` | `SUMIFS('Др проекты'!AC; AC<>0; заказчик; BK="Да")` — производственные долги (отгружено) vs `BK="Нет"` (в реализации) |

## 4. Найденные проблемы (важно до переноса)

| № | Проблема | Последствие |
|---|---|---|
| 1 | **`IMPORTRANGE` из внешней Google-книги** (`1tbQcUs4Vci9U7Wtcfyy…`) питает `База сырья`, `19.20-7п`, `реестр АПП` | В xlsx лежат **кэшированные** значения (`__xludf.DUMMYFUNCTION`), а не живые данные. Нужен доступ к книге-источнику |
| 2 | **`#REF!` в живых формулах**: `Приход ГП` — 139, `Минимальные остатки` — 81, `Др проекты` — 9, `Спецификации` — 7, `База сырья` — 4 | Часть расчётов уже возвращает ошибку; цифры в отчётах занижены |
| 3 | **8 137 уникальных формул в `База сырья`** и **10 493 в `Склад ТМЦ`** при ~3 000 строк | Формулы правились построчно вручную → строки считаются по-разному |
| 4 | **Самый цитируемый лист `19.20-7п` — скрытый** | Ключевая финансовая логика вне поля зрения пользователей |
| 5 | **Справочник менеджеров зашит в формулу**: `IF(K="Радикс";"Алитет"; IF(K="КарТел";"Артур"…)` | Новый менеджер = правка 4 000 формул |
| 6 | **Константы в ячейках**: НДС 12%, маржа 10%, логистика 3%, отсрочка 30 дней, оклад 2 040 ₸ | Меняются правкой ячейки без истории |
| 7 | **Циклическая связь** `План` → `Спецификации` → `База сырья` → `Спецификации` → `План` | Порядок пересчёта неопределён |
| 8 | `Долги ЦМК` — **пустой лист**; `Прайс` и `Прайс 2024` дублируются | Непонятно, что актуально |
| 9 | В `свод Акерке` подпись «обновлено 05.06.2026» при данных 2024–2025 | Актуальность под вопросом |

Существующая `backend/prisma/schema.prisma` уже покрывает базу: `Article`, `Material`, `BomItem`, `Customer`, `Order`, `OrderLine`, `PaymentDocument`, `Payment`, `MinStockLevel`, `ProductionPlanItem` и т. д.

### 5.1. Новое: организационный контур

Покрывает: «Подразделение» (ЦМК‑1, 7п, 71п, 74п), «Номер заказа АС / А77», юрлица.

```prisma
/// Юрлицо группы: Аврора Сервис ТОО, Аврора 77 ТОО, ЭТЗ Аврора, Wisk Telecom.
model LegalEntity {
  id        String   @id @default(uuid()) @db.Uuid
  name      String   @unique @db.VarChar(150)
  shortCode String   @unique @map("short_code") @db.VarChar(20)  // "АС", "А77"
  binIin    String?  @map("bin_iin") @db.VarChar(12)
  isActive  Boolean  @default(true) @map("is_active")

  divisions Division[]
  orders    Order[]
  @@map("legal_entities")
}

/// Подразделение: ЦМК-1, 7п_Телеком, 71п, 74п.
model Division {
  id            String  @id @default(uuid()) @db.Uuid
  legalEntityId String  @map("legal_entity_id") @db.Uuid
  code          String  @unique @db.VarChar(20)
  name          String  @db.VarChar(100)

  legalEntity LegalEntity @relation(fields: [legalEntityId], references: [id])
  projects    Project[]
  orders      Order[]
  @@map("divisions")
}

/// Группа проектов: "KZ-Телеком-Теле2-2025", "БМК", "Госпиталь Талдыкурган".
model Project {
  id         String  @id @default(uuid()) @db.Uuid
  code       String  @unique @db.VarChar(60)
  name       String  @db.VarChar(200)
```

## 9. Что нужно от заказчика

1. **Доступ к книге-источнику `IMPORTRANGE`** (`docs.google.com/spreadsheets/d/1tbQcUs4Vci9U7WtcfyyZmKF8Vorp5Bog1P…`). Без неё `База сырья`, `19.20-7п` и `реестр АПП` переносятся только снимком на дату выгрузки — а `19.20-7п` цитируется 27 600 раз.
2. **`Прайс` или `Прайс 2024`** — какой считать актуальным.
3. **Оргструктура**: полный список подразделений (`ЦМК-1`, `7п_Телеком`, `71п`, `74п`) и их привязка к юрлицам.
4. **Лист `Долги ЦМК` пуст** — он нужен или это остаток от прежней версии?
5. **`#REF!` в 240 формулах** — восстанавливать логику или считать эти расчёты отменёнными.
6. **Правила отсрочки**: 30 дней зашито в формулу. Одинаково для всех заказчиков или зависит от договора?
